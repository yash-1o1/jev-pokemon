# Game session operation

- Use GPT-6 Luna through the Decisions API as the primary game controller. GPT-5.6 Terra through Responses handles detected stalls. Keep achievement runs attached to the existing `--achievements` session and its in-game save.
- The play runner tracks separate per-model ledgers but enforces one shared 2.5 million token daily safety cap across both models. A 10,000-token request reserve is held to avoid exceeding the cap; RetroArch pauses at that safety threshold and resumes after the 00:00 UTC reset. Keep local ledgers in ignored `.local/` storage. The API Usage dashboard is authoritative if other clients use the same project; verify pool availability before raising a cap.
- Watch bounded runs' positions and screenshots. If Decisions repeats ineffective inputs, let the watchdog start a bounded Terra recovery episode; Terra returns control after 60 Terra actions or when the next battle is visible. The runner continues with Decisions after the handoff. Interaction progress compares the full screen; movement progress uses game position. Both controllers receive recent action outcomes and must change inputs when an action visibly has no effect.
- Preserve the active game's rules: Dark, male, no Pokémon nicknames; save in game every 30 real minutes and before missable events. Recover a missed event only from an earlier in-game save, never from a fresh game.
- Record only achievements that have been independently verified as unlocked. Keep local keys, saves, and checkpoints in ignored `.local/` files.
